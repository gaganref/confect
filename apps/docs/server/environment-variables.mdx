Confect provides a `ConfigProvider` that is compatible with the Convex runtime, where `process.env` is not enumerable. Confect sets it automatically for every function that runs in the Convex runtime—queries, mutations, actions, and HTTP API handlers—so Effect's [`Config`](https://effect.website/docs/configuration/) module works out of the box.

[Node actions](/server/node-actions) are the exception. They run in the Node.js runtime, where `process.env` behaves like an ordinary object, so they use Effect's default [`ConfigProvider.fromEnv`](https://effect.website/docs/configuration/#loading-configuration-from-environment-variables) instead. Reading environment variables works the same way in both runtimes.

## Reading environment variables

Use `Config` from Effect to read [Convex environment variables](https://docs.convex.dev/production/environment-variables) in your function handlers.

```ts confect/settings.impl.ts
import { FunctionImpl } from "@confect/server";
import * as Config from "effect/Config";
import * as Effect from "effect/Effect";

import databaseSchema from "./_generated/schema";
import settings from "./settings.spec";

const getApiKey = FunctionImpl.make(databaseSchema, settings, "getApiKey", () =>
  Config.String("API_KEY").pipe(Effect.orDie),
);
```

Combinators that read a single variable work as expected—`Config.String`, `Config.Number`, `Config.Boolean`, `Config.withDefault`, `Config.option`, and `Config.nested`, among others.

```ts
Config.Int("MAX_RESULTS").pipe(Config.withDefault(100));
```

## Built-in deployment addresses

Convex supplies `CONVEX_SITE_URL` and `CONVEX_CLOUD_URL` for every app and component. Read them directly with `Config`, or with `process.env` where you already use it.

```ts
import * as Config from "effect/Config";

const siteUrl = Config.String("CONVEX_SITE_URL");
const cloudUrl = Config.String("CONVEX_CLOUD_URL");
```

Both names are reserved in [backend environment declarations](/server/backend-declaration#envts) and component slot descriptors. `Env.make` and `Component.make` reject them at compile time and throw a `ReservedEnvKey` at runtime when types are bypassed. Declaration codegen also rejects them in slot declarations and mount bindings for apps and components. The error names the slot and explains that Convex supplies the address. A third-party component that requires either slot cannot be mounted.

A declared slot with either name could override the component's own address through a mount binding. To use Convex's address, remove the slot and its mount binding, then read the built-in directly. To pass a different address, rename the slot and its bindings to a custom name such as `SERVICE_URL`.

## Automatic variables

Use `Env.automatic(field)` for a required variable that your framework supplies, such as the stage or an origin. Declare it in the component's `confect/env.ts`:

```ts
import { Env } from "@confect/core";

export default Env.make("email", {
  STAGE: Env.automatic(Env.string()),
});
```

Handlers yield `env.STAGE` as an ordinary `Config`. Codegen binds the slot through every parent under the same name. The root declares `STAGE` once, even when several children need it. Automatic slots never become open mount settings and never gain a mount prefix.

A parent can declare the same automatic slot with the same kind, values and optionality. An ordinary slot with that name, or an automatic slot of another shape, fails codegen with `AutomaticSlotConflict`. Two sibling mounts whose automatic slots of one name differ fail the same way, and the error's `declaredBy` names the other mount. Use `Env.automatic` with the child's field, or rename the conflicting slot. An automatic slot is always required; the manifest schema refuses an optional one.

`Manifest.Values<typeof manifest>` omits automatic slots. `Manifest.Automatic<typeof manifest>` describes the values your framework supplies through [`Backend.automatic`](/guides/alchemy#supply-automatic-values). `Mount.make` rejects an explicit binding for an automatic slot.

## Provider choices

Use `Env.providers` to declare a choice and the settings each provider needs:

```ts confect/env.ts
import { Env } from "@confect/core";

export default Env.make("email", {
  EMAIL_PROVIDER: Env.providers({
    ses: { SES_REGION: Env.string(), SES_KEY: Env.secret() },
    resend: { RESEND_API_KEY: Env.secret() },
  }),
});
```

Codegen declares `EMAIL_PROVIDER` as a string selector. It expands `SES_REGION`, `SES_KEY`, and `RESEND_API_KEY` into ordinary optional slots. Their manifest descriptors carry `provider: { selector, name, required }`, where `selector` is `EMAIL_PROVIDER`, the selector they belong to. An optional field inside a provider remains optional when that provider is selected. All slot names follow the same validation and reserved-name rules as other environment variables.

Every expanded name must be unique in the backend's env. A setting named like a top-level slot or a selector is a type error at `Env.make`. A setting name shared by two providers, or by two selectors, compiles but `Env.make` throws `DuplicateEnvKey`, naming both declarations.

A handler yields `env.EMAIL_PROVIDER` and receives `{ choice, providers }`. For `EMAIL_PROVIDER="resend"`, `providers.resend.RESEND_API_KEY` is a `Redacted<string>` and `providers.ses` is absent. Each named provider's required settings must exist.

The selector also accepts JSON for failover or a pool:

```json
{ "active": "ses", "standby": ["resend"] }
```

```json
{ "pool": ["ses", "resend"] }
```

`Env.ProviderChoice<"ses" | "resend">` types these choices. Standby lists and pools must be nonempty. Decoding rejects unknown provider names, an active provider repeated in standby, an empty pool, and missing required settings for any named provider. The component owns failover and pool behavior.

The stack supplies [provider choices as plain data](/guides/alchemy#write-a-provider-choice). `Backend` checks each choice with `Env.providerChoice`, the schema a handler decodes it with, and writes the object forms as JSON. Types check the choice's names but do not require the settings of its standby providers. `Backend` checks required settings at runtime.

## Collections

`Config.Array` and `Config.Record` read a collection from a single delimited variable, so they work in the Convex runtime like any other combinator. Pass them to `Config.schema` with the variable's name.

Given `ALLOWED_ORIGINS="https://a.example,https://b.example"`:

```ts
import * as Schema from "effect/Schema";

Config.schema(Config.Array(Schema.String), "ALLOWED_ORIGINS");
// ["https://a.example", "https://b.example"]
```

Given `FEATURE_LIMITS="uploads=10,exports=5"`:

```ts
Config.schema(Config.Record(Schema.String, Schema.String), "FEATURE_LIMITS");
// { uploads: "10", exports: "5" }
```

Both default to `","` as the separator, and `Config.Record` to `"="` between key and value; pass `separator` or `keyValueSeparator` to change them. Neither trims whitespace around elements, so write the variable without spaces after the separator, or map over the result to trim.

The collection has to live in one variable. Effect's default provider can also assemble one from several variables—`ORIGINS_0` and `ORIGINS_1` for an array, `FEATURE_LIMITS_UPLOADS` for a record—because it reads the whole environment and discovers the keys under a prefix. Confect's provider resolves each config path to a single variable and never reports child keys, so that spread-out form fails with `Expected array at ["ORIGINS"]` or `Expected object at ["FEATURE_LIMITS"]`. It works in [Node actions](/server/node-actions), which use the default provider; avoid it if the handler might later move to the Convex runtime.

## Custom config provider

The `ConvexConfigProvider` module is exported from `@confect/server`. `ConvexConfigProvider.make()` takes no arguments and returns the provider Confect already installs for you.

```ts
import { ConvexConfigProvider } from "@confect/server";

const provider = ConvexConfigProvider.make();
```

It resolves each config path to a single environment variable, joining the path segments with `"_"`. `Config.nested(Config.String("KEY"), "API")` therefore reads `API_KEY`. An empty string counts as a missing value, so `Config.withDefault` and `Config.option` recover from it.

To override the provider for part of a handler, provide `ConfigProvider.ConfigProvider` as a service.

```ts confect/settings.impl.ts
import { ConvexConfigProvider, FunctionImpl } from "@confect/server";
import * as Config from "effect/Config";
import * as ConfigProvider from "effect/ConfigProvider";
import * as Effect from "effect/Effect";

import databaseSchema from "./_generated/schema";
import settings from "./settings.spec";

const getApiKey = FunctionImpl.make(databaseSchema, settings, "getApiKey", () =>
  Config.nested(Config.String("KEY"), "API").pipe(
    Effect.provideService(
      ConfigProvider.ConfigProvider,
      ConvexConfigProvider.make(),
    ),
    Effect.orDie,
  ),
);
```
