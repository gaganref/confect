A Confect component is a Convex component with Effect handlers and a generated public contract. This walkthrough uses the checked-in `scripts/consumer/` fixture. File paths are relative to the host project. Install `@confect/core`, `@confect/server`, `@confect/cli`, `effect` and `convex`; tests also use `@confect/test`, `convex-test`, Vitest and Vite's `import.meta.glob` types.

## Declare a component

Author the component's env and app in its own `confect/` directory, with `kind: "component"`. The env name becomes the Convex component name. The counter needs no environment variables:

```ts components/counter/confect/env.ts
import { Env } from "@confect/core";
export default Env.make("counter", {});
```

```ts components/counter/confect/app.ts
import { App } from "@confect/core";
import env from "./env";
export default App.make({ kind: "component", env });
```

Run `confect codegen --component-dir components/counter/convex`. Codegen writes this definition:

```ts components/counter/convex/convex.config.ts
// Generated by `confect codegen` from confect/app.ts. Do not edit.
import { defineComponent } from "convex/server";

const component = defineComponent("counter");

export default component;
```

With declared entries, codegen emits `defineComponent(name, { env: { ... } })` with their Convex validators. An empty env emits no options object. Keep a `name` in the enclosing `package.json`; the generated ID scope derives from the package name and the component directory's package-relative path.

Declare the component's relative HTTP API and handlers:

```ts components/counter/confect/api.ts
import * as Schema from "effect/Schema";
import * as HttpApi from "effect/http-api/HttpApi";
import * as HttpApiEndpoint from "effect/http-api/HttpApiEndpoint";
import * as HttpApiGroup from "effect/http-api/HttpApiGroup";
import * as HttpApiSchema from "effect/http-api/HttpApiSchema";
export const CounterApi = HttpApi.make("counter").add(
  HttpApiGroup.make("health").add(
    HttpApiEndpoint.get("health", "/health", {
      success: Schema.String.pipe(HttpApiSchema.asText()),
    }),
  ),
);
```

```ts components/counter/confect/http.ts
import { Http } from "@confect/core";
import * as Effect from "effect/Effect";
import * as HttpApiBuilder from "effect/http-api/HttpApiBuilder";
import { CounterApi } from "./api";
export default Http.make({
  api: CounterApi,
  handlers: HttpApiBuilder.group(CounterApi, "health", (handle) =>
    handle.handle("health", () => Effect.succeed("component ready")),
  ),
});
```

Codegen writes the component's own HTTP entry point:

```ts components/counter/convex/http.ts
// Generated by `confect codegen` from confect/http.ts. Do not edit.
import { HttpRouter } from "@confect/server";
import schema from "../confect/_generated/schema";
import http from "../confect/http";

export default HttpRouter.forSchema(schema)(http.routes, { api: http.api });
```

Write tables under `confect/tables/` and functions in sibling `*.spec.ts` / `*.impl.ts` files using the same APIs as an application. Codegen writes IDs, schemas, services, refs, registered functions and `confect/_generated/component.ts`, the publishable contract that `Component.contract(spec, scope, tables)` builds. Only public functions enter that contract. Breaking change: replace `Component.make(spec, scope, tables)` with `Component.contract(spec, scope, tables)`. Rerun `confect codegen` for generated callers.

A component's `_generated/services.ts` omits `MutationCtx`, `QueryCtx` and `ActionCtx`, so a handler that yields one fails to type-check. Use its typed database, runner, storage and scheduler services instead.

Host applications still receive all three raw context tags. `@confect/server` keeps exporting them for middleware authors. Middleware owns removing raw contexts from the context it passes to downstream handlers.

Run Convex's component codegen after Confect's codegen when preparing the package for publication:

```sh
confect codegen --component-dir components/counter/convex
convex codegen --component-dir components/counter/convex
```

After upgrading to the fork based on upstream 10.3.1, rerun `confect codegen` for both the component and host. For local iteration, run `confect dev --component-dir components/counter/convex` and a separate host `confect dev` alongside the Convex development workflow.

### Group a table's rows

A table's rows can belong to rows of another table in the component. `.group` names the required id field that holds that owner, and the field's table is the owner's table:

```ts title="confect/tables/emails.ts"
import { Table } from "@confect/core";
import * as Schema from "effect/Schema";
import { Id } from "../_generated/id";

export default Table.make(() =>
  Schema.Struct({ batchId: Id("batches"), to: Schema.String }),
).group("batchId");
```

`.group` takes only a required id field. `.group("to")`, `.group("nope")` and an optional id are type errors. `Component.contract(spec, scope, tables)` takes tables beside system table names, such as `[batches, emails, "_storage"]`, and refuses a grouped table whose id is not one of the listed tables in the component's scope, such as an id from another component or an application id. `Component.groups(contract)` returns `{ emails: { key: "batchId", table: "batches" } }`, and its type keeps those literals. Passing table names only, or naming them as the third type argument, publishes no groups. Generated `_generated/component.ts` passes each table, so a host or a lint rule reads a component's groups from its published contract: `Component.groups(contract)`. Loading the contract builds no table schema; reading its groups does.

## Mount it in a host

The host declares its own env, then lists the component's `convex.config` definition and a [`Mount.make`](#reach-a-mounts-client) mount of it. The mount supplies the mount name; there is no `App.use` API:

```ts confect/env.ts
import { Env } from "@confect/core";
export default Env.make("consumer", {
  INSTALL_MARKER: Env.optional(Env.string()),
});
```

```ts confect/app.ts
import { App, Mount } from "@confect/core";
import Counter from "../components/counter/client";
import counter from "../components/counter/convex/convex.config";
import env from "./env";
export default App.make({
  env,
  components: [counter],
  mounts: [Mount.make(Counter, { name: "counter", httpPrefix: "/counter" })],
});
```

Codegen writes `defineApp` and Convex's `app.use`:

```ts convex/convex.config.ts
// Generated by `confect codegen` from confect/app.ts. Do not edit.
import { defineApp } from "convex/server";
import { v } from "convex/values";
import counter from "../components/counter/convex/convex.config";

const app = defineApp({
  env: {
    INSTALL_MARKER: v.optional(v.string()),
  },
});

app.use(counter, {
  name: "counter",
  httpPrefix: "/counter",
});

export default app;
```

The fixture's component has no env slots to bind. For a component with slots, pass `env` to `Mount.make`, as shown in [Backend Declaration](/server/backend-declaration#appts). A binding is a constant string or an entry from the host's env. Required slots need required entries; literal values must fit the slot; unknown slots and entries from another backend fail to typecheck. Codegen emits constant bindings directly and env entries as `app.env.KEY`.

Author the host's authentication providers:

```ts confect/auth.ts
import { Auth } from "@confect/core";
import app from "./app";
export default Auth.make(app, {
  providers: [
    { domain: "https://login.example.edu", applicationID: "consumer" },
  ],
});
```

Codegen writes the Convex provider configuration:

```ts convex/auth.config.ts
// Generated by `confect codegen` from confect/auth.ts. Do not edit.
import type { AuthConfig } from "convex/server";

export default {
  providers: [
    {
      domain: "https://login.example.edu",
      applicationID: "consumer",
    },
  ],
} satisfies AuthConfig;
```

Author the host's HTTP API separately from its app declaration:

```ts confect/http.ts
import { Http } from "@confect/core";
import * as Effect from "effect/Effect";
import * as Schema from "effect/Schema";
import * as HttpApi from "effect/http-api/HttpApi";
import * as HttpApiBuilder from "effect/http-api/HttpApiBuilder";
import * as HttpApiEndpoint from "effect/http-api/HttpApiEndpoint";
import * as HttpApiGroup from "effect/http-api/HttpApiGroup";
import * as HttpApiSchema from "effect/http-api/HttpApiSchema";
const api = HttpApi.make("host").add(
  HttpApiGroup.make("health").add(
    HttpApiEndpoint.get("health", "/health", {
      success: Schema.String.pipe(HttpApiSchema.asText()),
    }),
  ),
);
export default Http.make({
  api,
  handlers: HttpApiBuilder.group(api, "health", (handle) =>
    handle.handle("health", () => Effect.succeed("host ready")),
  ),
});
```

Codegen writes this HTTP entry point, including `{ api: http.api }` for endpoint labels in Convex logs and the dashboard:

```ts convex/http.ts
// Generated by `confect codegen` from confect/http.ts. Do not edit.
import { HttpRouter } from "@confect/server";
import schema from "../confect/_generated/schema";
import http from "../confect/http";

export default HttpRouter.forSchema(schema)(http.routes, { api: http.api });
```

Import `env.ts` in handlers, never `app.ts`. Component definitions load only during Convex config analysis. Without `confect/app.ts`, the declaration is opt-in and you manage `convex/convex.config.ts` yourself with Convex's API.

## Reach a mount's client

A component package describes itself to hosts with `Component.make`, exported from its `./client` entry, as Convex's `defineComponent` names a component. The descriptor names its `init` when it has one, and declares the env slots a mount binds and the constructor that builds the client from the native mount, followed by the mount's options when it takes any:

```ts components/counter/client.ts
import { Component } from "@confect/core";
import * as Schema from "effect/Schema";
import contract from "./confect/_generated/component";
import type spec from "./confect/_generated/spec";

export default Component.make("counter", {
  contract,
  env: { COMPONENT_REQUIRED: Schema.String },
  client: (native: Component.Api<typeof spec>) =>
    Component.bind(contract, native),
});
```

A host declares each mount in its own `confect/<mount>.ts` with `Mount.make`, as Convex's `app.use` installs one. `env` is typed from the descriptor's slots, and takes a constant or an entry of the host's env. `options` is typed from the client constructor's parameters after the native mount: absent when it takes none, optional or required as the constructor declares it.

```ts confect/first.ts
import { Mount } from "@confect/core";
import Counter from "../components/counter/client";

export const First = Mount.make(Counter, {
  name: "first",
  httpPrefix: "/first",
  env: { COMPONENT_REQUIRED: "first-required" },
});
```

A component that declares `init`, an internal mutation in its `install` group, takes install `args` at each mount, as Convex's preview `app.use(component, { args })` does. `args` is typed from `init`'s args. A callback slot, a `Callback.handle(contract)` field, takes an internal host ref whose args, returns and kind match the contract:

```ts confect/bulkEmail.ts
export const BulkEmail = Mount.make(Email, {
  name: "bulkEmail",
  args: {
    fromName: "School office",
    onEvent: refs.internal.circulars.onEmailEvent,
  },
});
```

The mount records its `args`. Nothing runs `init` on a push yet. A component without `init` takes no `args`.

A descriptor that passes its `contract` gives each mount `callbackArgs(slot)`: the args a callback slot's contract sends, with the component's ids typed for that mount. The host function that answers the callback declares them as its args:

```ts confect/circulars.spec.ts
FunctionSpec.internalMutation({
  name: "onEmailEvent",
  args: () => BulkEmail.callbackArgs("onEvent"),
  returns: () => Schema.Null,
});
```

An id from one mount's `callbackArgs` does not typecheck as another mount's. A descriptor without `contract` has no `callbackArgs`.

A mount is a `Context.Reference` keyed `mount/<name>`. Any handler yields it, `const counter = yield* First`, and gets the client over that installation with no Layer to provide. The client's methods still need the runners they call through. `Effect.provideService(First, fake)` replaces the client inside one effect, which is how a test swaps it. A mount file imports no `convex.config`, so function bundles can import it. `Auth.siteUrl(First, "/jwks.json")` points at a mount's HTTP routes; a mount without an `httpPrefix` fails to typecheck there.

List each mount in `App.make`'s `mounts` and the component's `convex.config` definition in its `components`, and codegen writes one `app.use` per mount into `convex/convex.config.ts`.

## How HTTP routes compose

The host serves `/health`. The counter declares `/health` relative to its installation, so the mount serves `/counter/health`. Convex selects each installation's HTTP action. `HttpRouter.forSchema` prefixes the component's Effect router with the pathname of its `CONVEX_SITE_URL`, including ancestor mount prefixes; it preserves the original request and body. Host middleware does not wrap the component's routes.

Codegen calls `Http.routes(app, http)` to validate the route inventory. It returns a `Result` failure for:

- `RouteUnderMountPrefix` when a host endpoint or Scalar docs page is at or under a mount prefix, regardless of method. Convex would otherwise let it shadow the component.
- `DuplicateRoute` when method and path repeat, including declared parameter names normalised to the same placeholder. Each Convex component checks its own routes during codegen.
- `OverlappingMountPrefixes` when mount prefixes overlap on path boundaries. This check and mount-prefix reservation run even without `http.ts`.

These checks compare declared paths; they are not a general proof that all dynamic route patterns are disjoint.

## Contracts and callbacks

Bind the generated public contract to the installation's generated registry entry:

```ts confect/component.ts
import { Component } from "@confect/core";
import contract from "../components/counter/confect/_generated/component";
import { components } from "./_generated/components";
export const counter = Component.bind(contract, components.counter);
```

Use `QueryRunner`, `MutationRunner`, `ActionRunner` or `Scheduler` with the bound references. Arguments and returns use decoded types, and declared errors enter the Effect error channel. The registry at `confect/_generated/components` is safe during clean-checkout codegen; importing the registry from `convex/_generated/api` can fail before Convex has generated it.

`Component.id(counter, table)` describes an installed component's table ID in host schemas; `Component.schema(counter, codec)` rebinds IDs inside an exported codec. Use generated `Id` inside the component. Scopes distinguish installations in TypeScript, not ID strings or authorization. Foreign IDs compile to string validators; validate untrusted references with the owning component. Very deep mounts can lose compile-time ID separation.

A callback lets a component call a host function. Declare an id of the form `"<component>/<event>"`. This is the first contract in the fixture's callback module:

```ts components/counter/confect/callbacks.ts
import { Callback } from "@confect/core";
import * as Schema from "effect/Schema";
export const OnResult = Callback.mutation("counter/onResult", {
  args: () => ({ value: Schema.FiniteFromString }),
  returns: () => Schema.FiniteFromString,
});
```

Codegen checks contracts exported from `confect/callbacks.ts`. Each id must start with the name passed to `defineComponent`, followed by `/` (for a declared component, this is the name in `Env.make`). It checks the exports without evaluating schema thunks. A component without this file passes.

Use `Callback.handle(OnResult)` in the component's function args or tables. A `Callback.handle` slot lowers to `v.function` and requires Convex 1.49 or later. On the wire it is a string; after decoding it is a runnable reference branded with the contract id. Handles for different ids are incompatible even when their shapes match. The fixture's component spec is:

```ts components/counter/confect/counter.spec.ts
import { Callback, FunctionSpec, GroupSpec } from "@confect/core";
import * as Schema from "effect/Schema";
import { OnResult } from "./callbacks";
export default GroupSpec.make()
  .addFunction(
    FunctionSpec.publicQuery({
      name: "increment",
      args: () => ({ value: Schema.Finite }),
      returns: () => Schema.Finite,
    }),
  )
  .addFunction(
    FunctionSpec.publicMutation({
      name: "notify",
      args: () => ({
        value: Schema.Finite,
        onResult: Callback.handle(OnResult),
      }),
      returns: () => Schema.Finite,
    }),
  );
```

The host satisfies the contract with a generated reference. This excerpt from `confect/hello.impl.ts` creates a handle and passes it to the component:

```ts confect/hello.impl.ts
import { Callback, FunctionImpl, GroupImpl } from "@confect/server";
import * as Effect from "effect/Effect";
import * as Layer from "effect/Layer";
import {
  OnCheckedArgs,
  OnResult,
} from "../components/counter/confect/callbacks";
import schema from "./_generated/schema";
import refs from "./_generated/refs";
import { MutationRunner, QueryRunner } from "./_generated/services";
import { counter } from "./component";
import hello from "./hello.spec";
const notify = FunctionImpl.make(schema, hello, "notify", ({ value }) =>
  Effect.gen(function* () {
    const runner = yield* MutationRunner;
    const handle = yield* Callback.create(
      OnResult,
      refs.internal.hello.onResult,
    );
    return yield* runner.runMutation(counter.counter.notify, {
      value,
      onResult: handle,
    });
  }).pipe(Effect.orDie),
);
```

The host's `onResult` spec uses the same `Schema.FiniteFromString` argument and return codecs as `OnResult`. `Callback.create` checks function kind, encoded args and returns, and declared errors, including middleware errors. The host may declare fewer errors. It also compares compiled Convex validators before asking Convex for a handle; a mismatch fails with `CallbackContractMismatch`. Matching validators cannot distinguish every refinement or codec, so reuse the contract's schemas and error classes.

To forward context through a mutation or action callback, decode it with
`Callback.handle(OnResult, { reservedArgument: "context" })`. The host function
must reserve the same name. Runners and the scheduler inject the value from
`RegisteredFunction.Forward` after encoding domain arguments. The handle stays
a string on the wire, so each receiving schema declares the reservation. Omit
the option for targets that accept only domain arguments. Query handles cannot
reserve an argument. This transports a value without authenticating it. The
host owns its trust policy, including whether to accept an incoming run id.

The component runs the handle with its runner or scheduler. No generated callback adapter is needed. The fixture decodes `21`, calls the host which adds `21`, and adds `1` in the component, returning `43`. Keep callback contracts in a client-safe entry point without server implementation imports.

## Nested components

Components may mount components. In a declared component, list each child's definition and mount in its `App.make({ env, components, mounts })`; codegen writes `defineComponent(...).use(child, { name, httpPrefix, env })`. Without a declaration, write the native component configuration yourself. Run codegen for each component directory before generating its parent.

Bind a child contract with `Component.bind(childContract, components.child, { parentScope: scope })`, importing `scope` from the parent's `_generated/id`. This keeps child IDs associated with the enclosing installation when its contract returns them. Root host bindings omit `parentScope`. Nested HTTP prefixes accumulate through Convex's installation site URL.

Component handlers use their own database, scoped storage services and scheduler. Application `Auth` and unified `Storage` are unavailable inside a component. Pass identity explicitly in arguments. Native `.paginate()` works in component readers, including search results. A query may paginate once across the host and every component query it calls. A second `.paginate()` throws. Use [`QueryStream.paginate`](/server/database/streams#paginating-a-stream) for a second paginated index read. Confect does not rewrite plain Convex handlers.

## Wrap an official component

An official Convex component ships a client whose methods take a native ctx first and return a promise. `OfficialComponent.make` lifts such a client into Effect so Confect handlers call it without a ctx. This client is the shape a component's package ships:

```ts limiter/client.ts
import {
  createFunctionHandle,
  type DefaultFunctionArgs,
  type FunctionArgs,
  type FunctionReference,
  type FunctionReturnType,
} from "convex/server";
import type { ComponentApi } from "./_generated/component.js";

type RunQueryCtx = {
  runQuery: <Q extends FunctionReference<"query", "internal">>(
    query: Q,
    args: FunctionArgs<Q>,
  ) => Promise<FunctionReturnType<Q>>;
};
type RunMutationCtx = {
  runMutation: <M extends FunctionReference<"mutation", "internal">>(
    mutation: M,
    args: FunctionArgs<M>,
  ) => Promise<FunctionReturnType<M>>;
};

export class Limiter {
  constructor(private readonly component: ComponentApi) {}

  remaining(ctx: RunQueryCtx, key: string): Promise<number> {
    return ctx.runQuery(this.component.lib.remaining, { key });
  }

  consume(ctx: RunMutationCtx, key: string, count: number): Promise<number> {
    return ctx.runMutation(this.component.lib.consume, { key, count });
  }

  async schedule(
    ctx: RunMutationCtx,
    fn: FunctionReference<"mutation", "internal">,
    fnArgs: DefaultFunctionArgs,
  ): Promise<string> {
    const handle = await createFunctionHandle(fn);
    return ctx.runMutation(this.component.lib.schedule, { handle, fnArgs });
  }
}
```

Generic methods lift with their inferred parameters too.

Lift it once, beside the host's mount:

```ts confect/limiter.ts
import { OfficialComponent } from "@confect/server";
import { Limiter } from "limiter";
import { components } from "./_generated/components.js";

export const limiter = OfficialComponent.make(
  "limiter",
  new Limiter(components.limiter),
);
```

`limiter("remaining", key)` is an `Effect<number, never, QueryRunner>` and `limiter("consume", key, 1)` an `Effect<number, never, MutationRunner>`. Each method's runner comes from the ctx its first parameter accepts. It is `QueryRunner` when query, mutation and action ctxs all satisfy the parameter, `MutationRunner` when mutation and action ctxs do, and `ActionRunner` when only an action ctx does. A method an action ctx cannot satisfy, such as one that needs `ctx.db`, is left out of the method names. The call reads the native ctx from the running handler and passes your arguments after it:

```ts confect/jobs.impl.ts
import { FunctionImpl, OfficialComponent } from "@confect/server";
import * as Effect from "effect/Effect";
import schema from "./_generated/schema.js";
import refs from "./_generated/refs.js";
import jobs from "./jobs.spec.js";
import { limiter } from "./limiter.js";

const start = FunctionImpl.make(schema, jobs, "start", ({ key }) =>
  Effect.gen(function* () {
    if ((yield* limiter("consume", key, 1)) < 0) return null;
    const call = yield* OfficialComponent.encodeCall(
      refs.internal.jobs.run,
      { key },
      { carrier: "none" },
    );
    yield* limiter("schedule", call.reference, call.args);
    return null;
  }),
);
```

`encodeCall` encodes a ref's arguments through its codecs and returns `{ reference, args }`, the function reference and wire record an official method expects. Its third argument is required.

A carrier is the value returned by [`RegisteredFunction.Forward`](/server/functions#reserved-arguments). `{ carrier: "forward" }` adds that value when the target reserves an argument and is a mutation or action. With no `Forward` provider or no active span, nothing is added. `{ carrier: "none" }` preserves the encoded arguments without a carrier, for components that replay or compare stored arguments. Queries never receive a carrier.

`encodeField(ref, key, value)` encodes one declared argument field, for a method that takes a single field rather than a whole argument record.

A rejected promise is a defect, not a typed error. The effect dies with `ComponentCallFailed`, carrying the `component` name, the `method` and the rejection as `cause`. Calling outside a Confect handler dies with `<component> called outside a Confect handler`.

## What codegen rejects

Codegen protects hand-written config files. Move their contents into declarations and delete them before opting in. The messages below omit terminal styling and the leading cross; placeholders stand for values from your project.

| Tag                            | Diagnostic text                                                                                                                             |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------- |
| `HandWrittenConvexFileError`   | Found a hand-written `<convexPath>`. `confect codegen` writes it from `<declarationPath>` now; move its contents there and delete the file. |
| `InvalidConvexConfigError`     | Convex config `<configPath>` could not be evaluated: `<reason>`                                                                             |
| `ComponentNodeGroupError`      | Group "`<groupPath>`" in `<specPath>` uses the Node runtime. Convex components do not support Node.js functions.                            |
| `InvalidDeclarationError`      | Declaration `<declarationPath>` is invalid: `<reason>`                                                                                      |
| `InvalidManifestSectionError`  | Manifest section "`<sectionKey>`" is invalid: `<reason>`                                                                                    |
| `DeclarationKindMismatchError` | Declaration `<declarationPath>` declares kind "`<declaredKind>`", but the target directory is kind "`<targetKind>`".                        |
| `CallbackPrefixError`          | Callback contract "`<contractId>`" in `<declarationPath>` must start with "`<componentName>`/" for component "`<componentName>`".           |

A component's `confect/auth.ts` produces `InvalidConvexConfigError` with the reason `Components cannot configure application authentication. Pass identity explicitly through function arguments.` A non-`Http.make` HTTP default export produces `InvalidDeclarationError` with `it must default-export Http.make(...).` Declaration parsing wraps these tagged reasons in `InvalidDeclarationError`:

| Reason tag               | Reason text                                                                                                                     |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------- |
| `NotADeclaration`        | `<file>` must default-export `<expected>`.                                                                                      |
| `InvalidEnvKey`          | "`<key>`" is not a valid Convex environment variable name; use letters, digits and underscores, starting with a letter.         |
| `InvalidMountName`       | "`<mount>`" is not a valid mount name; use letters, digits and underscores, starting with a letter or underscore.               |
| `ForeignEnvBinding`      | The mount "`<mount>`" binds `<slot>` to `<key>` of the "`<backend>`" env, but this backend's env is "`<expectedBackend>`".      |
| `InvalidBinding`         | The mount "`<mount>`" binds `<slot>` to something other than a string or an entry of this backend's env.                        |
| `UnknownComponentImport` | The mount "`<mount>`" must pass the default export of a component's convex.config module, imported directly in the declaration. |
| `AuthForAnotherBackend`  | confect/auth.ts declares auth for the "`<backend>`" backend, but confect/app.ts declares "`<expectedBackend>`".                 |

`NotADeclaration` expects `App.make(...)` in `confect/app.ts` and `Auth.make(app, ...)` in `confect/auth.ts`. Route failures are wrapped in `InvalidDeclarationError` too, with these reason texts:

| Reason tag                 | Reason text                                                                                                                                                                          |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `RouteUnderMountPrefix`    | The app route `<method>` `<path>` is under the HTTP prefix `<httpPrefix>` of the mount "`<mount>`". Convex would let it shadow the component's routes; move it or change the prefix. |
| `DuplicateRoute`           | `<method>` `<path>` is declared twice (`<first owner>` and `<second owner>`).                                                                                                        |
| `OverlappingMountPrefixes` | The mounts "`<first.mount>`" (`<first.httpPrefix>`) and "`<second.mount>`" (`<second.httpPrefix>`) have overlapping HTTP prefixes.                                                   |

Owners print as `app`, `docs`, or `mount "<name>"`. Mount-prefix overlap is checked first, then host shadowing, then duplicate routes. Normal spec/impl validation still applies, including missing siblings, missing handlers, unfinalized layers and spec imports reaching `@confect/server`.

## Test with TestConfect

Import the generated test app to register declared components and their HTTP mounts automatically. This setup follows `scripts/consumer/consumer.test.ts.template`:

```ts consumer.test.ts
import { TestConfect } from "@confect/test";
import * as Effect from "effect/Effect";
import { expect, test } from "vitest";
import app from "./confect/_generated/testing.js";

const Test = TestConfect.TestConfect<typeof app.schema>();
const layer = TestConfect.layer(app);

test.each([
  ["/health", "host ready"],
  ["/counter/health", "component ready"],
])("declared HTTP route %s responds", (path, expected) =>
  Effect.runPromise(
    Effect.gen(function* () {
      const confect = yield* Test;
      const response = yield* confect.fetch(path);
      expect({
        status: response.status,
        body: yield* Effect.promise(() => response.text()),
      }).toEqual({ status: 200, body: expected });
    }).pipe(Effect.provide(layer)),
  ),
);
```

Codegen supplies each local component's schema and module loaders, registers each component from another package through its `<package>/testing` export, falling back to `<package>/test`, and supplies the declaration's installation paths and HTTP prefixes. The tests exercise both the host and mounted routes. The same fixture checks host-to-component calls, the callback result `43`, and validator mismatch rejection.

Nested installations and their full HTTP prefixes are generated automatically. The schema-based constructor remains available for manual registration and custom loaders. A component reused at multiple HTTP mounts needs a fresh router factory per HTTP module loader. See [mounted component HTTP tests](/guides/testing#fetch-mounted-component-routes) for module-cache and process-environment limits.

When publishing, ship built Convex functions and config, generated Convex `ComponentApi` declarations, the Confect contract, and all their transitive runtime/type dependencies. Export callback contracts separately. Confect does not run Convex codegen, build or publish the package for you; verify the packed package in a separate consumer.
