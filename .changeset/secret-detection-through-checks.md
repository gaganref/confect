Fix secret detection for a `Schema.Redacted` or `Schema.RedactedFromValue` schema that carries a check, with or without `Schema.brand`. Previously such a secret, and a struct, array, union or optional key that held one, did not count as secret: `confect codegen` left the function or table out of `secrets` in `confect/_generated/testing`, and on the kernel target `TestConfect.layer` wrote its raw value to snapshots, failure reports and diffs. It is now marked as an unchecked secret is.

On the kernel target, a secret in a union, or beneath a schema that stores its value in another form, is now marked wherever the stored value could have come from it. Previously the kernel chose a union's members by comparing the stored value with each member's decoded shape and walked only the members it chose, one after another. A renamed key (`Schema.encodeKeys`), a struct stored as a JSON string, a flipped schema or a secret `-0` could then reach snapshots and failure reports raw, and a snapshot could hold a marker inside a marked value, which its own restore refused. The kernel now leaves a member out only where the member's encoded form refuses the stored value by its JSON kind, a present field or a literal, and marks what every remaining member would mark, a whole mark winning. It follows a `Schema.Class` and a present `Schema.OptionFromNullOr` to their stored fields and marks only the secret ones. Beneath any other encoding, such as renamed keys or a JSON string, it marks the value whole.

This marks more than before, and a value marked whole is harder to read. A struct with renamed keys that holds a secret, a JSON string of one, and a plain member's value that a member marked whole could also have stored are each written as one marker, so their plain fields cannot be read in snapshots. Every string of four or more characters inside a value marked whole, plain fields included, becomes secret text, and failure reports write `[redacted]` wherever it appears. A secret number literal cannot be ruled out for `-0`, `NaN` or an infinity, which Convex stores as `$float`, so a plain number with one of those values beside it in a union is marked. When a table's own schema has an encoding, each stored field of its documents is marked instead of the document, and `_id` and `_creationTime` stay readable.
