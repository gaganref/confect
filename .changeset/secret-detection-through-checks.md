Fix secret detection for a `Schema.Redacted` or `Schema.RedactedFromValue` schema that carries a check, with or without `Schema.brand`. Previously such a secret, and a struct, array, union or optional key that held one, did not count as secret: `confect codegen` left the function or table out of `secrets` in `confect/_generated/testing`, and on the kernel target `TestConfect.layer` wrote its raw value to snapshots, failure reports and diffs. It is now marked as an unchecked secret is.

On the kernel target, a secret in a union, or beneath a schema that stores its value in another form, is now marked wherever the stored value could have come from it. Previously the kernel chose a union's members by comparing the stored value with each member's decoded shape and walked only the members it chose, one after another. A renamed key (`Schema.encodeKeys`), a struct stored as a JSON string, a flipped schema or a secret `-0` could then reach snapshots and failure reports raw, and a snapshot could hold a marker inside a marked value, which its own restore refused. The kernel now leaves a member out only where the member's encoded form refuses the stored value by its JSON kind, a present field or a literal, and marks what every remaining member would mark, a whole mark winning. Beneath a schema that holds a secret, a value whose schema has an encoding is marked whole. No encoding is followed, including one that passes its value through.

This marks more than before, and a value marked whole is harder to read. A `Schema.Class` with a secret field and a `Schema.OptionFromNullOr` of a struct with one each have an encoding, so they are now written as one marker, where they were previously marked at the secret field. Their plain sibling fields cannot be read in snapshots, an absent option is written as a marker, and failure reports write `[redacted]` wherever one of their sibling strings of four or more characters appears. The same holds for a struct with renamed keys, a JSON string of a struct, and a plain member's value that a member marked whole could also have stored. A secret number literal cannot be ruled out for `-0`, `NaN` or an infinity, which Convex stores as `$float`, so a plain number with one of those values beside it in a union is marked. When a table's own schema has an encoding, each stored user field of its documents is marked instead of the document. A document's own `_id` and `_creationTime` stay readable; a user field of either name below the document's root is marked like any other field.
