On the test kernel (`TestConfect.layer`'s `target: "kernel"`), a query or mutation can no longer reach the host's I/O. `fetch` and a multipart `formData()` reject with the errors the Convex binary gives, and `setTimeout` and `setInterval` end the function with the binary's error at once, even while the handler awaits the timer. Queries, mutations and actions other than Node actions find no `setImmediate` or `queueMicrotask`, as in Convex's isolate. `clearTimeout` and `clearInterval` stay allowed. Add the new `@confect/test/setup` to Vitest's `setupFiles` so these globals are guarded before any test module loads; a global a test replaces is guarded again when the next function starts, one it makes non-configurable refuses the function with `UnguardableGlobal` (`notConfigurable`), one whose install throws or is undone refuses it (`installFailed`), and one a function leaves replaced when it settles, read through the prototype chain, fails that function (`replacedWhileRunning`). Accessors that run code to fake the guard at settlement are hostile and out of scope. Each `TestConfect.layer` form, `registerComponent` and a component kit take `sources`, the modules as text, so the kernel reads each module's `"use node"` directive as Convex's bundler does. Without sources, a module that exports a plain Convex action is refused with `ActionRuntimeUnknown` when the kernel opens; declare a package kit's component runtime with `componentRuntimes`, such as `{ "workflow/workpool": "isolate" }`. `RegisteredNodeFunction.make` and `RegisteredConvexFunction` mark the actions they register with their runtime so the kernel can tell a Node action from an isolate one. The default convex-test target is unchanged.
