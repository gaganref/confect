A backend with route specs declares a guard: `HttpRouter.make(schema, routes, { api, guard })`. A guard is a plain Effect `HttpMiddleware` named with `Guard.make(name, middleware)`, and `Guard.none` is the explicit opt-out. Confect installs it as the router's first global middleware and runs it only for a request that dispatch would send to a route spec, OPTIONS on a route spec's path included with or without `Access-Control-Request-Method`, with `Routes.Route` and `Guard.Preflight` provided. Its inner effect never fails: a failure inside becomes Effect's response for it, and a failure whose response cannot be built becomes Effect's empty 500. A 5xx inside the guard is logged at error level with its cause as text, the request id and the route's function path, and no inherited annotation, log span or request URL. The guard is a pit of success for first-party product code, not a sandbox: no public Effect or Confect API lets product code change what the client receives after the guard settles, while deliberate reach into Effect internals is out of scope. Only a frozen snapshot of plain data crosses from product code to the guard: product code runs on a fiber of its own, started from Effect's scheduler and from a context whose request state is a stand-in, in a scope of its own, and its failure, its cause's text and its body, read up to the 1 MiB result cap, are all made there. A body past the cap answers 500 without the rest being read, and the guard's response is built from its own copy of the snapshot, every `Set-Cookie` value kept. A handler registered before the fiber ends, a finalizer's, an interrupted child fiber's or a response conversion's included, and Effect's `HttpMiddleware.cors`, `HttpMiddleware.compression` or `HttpApiBuilder.securitySetCookie` as a product global middleware, turns the response into Effect's 500 before the guard sees it, and one registered later never runs, so after the guard only transport conversion runs. CORS on a route path is the guard's, which may itself be `HttpMiddleware.cors`; the HTTP guide shows a global CORS middleware that skips route paths. Without Effect's request state at the key Confect reads, every route request answers 500. Classification uses the router's full registration set and configuration, HEAD precedence with GET fallback, wildcard bases and the synthesized OPTIONS chain, and a global middleware that rewrites the request into another route dies before dispatch. Each `Routes.make` registration carries its own identity. `HttpRouter.make` throws `Guard.MissingGuard` when its api list reflects a route spec and no guard is given, and refuses before serving a route spec registration without a guard, one the api list does not reflect as itself (`Guard.UnreflectedRoute`), one under a product prefix, an api route spec nothing registers, and an explicit OPTIONS or any-method route that could answer a route spec's request (`Guard.RouteShadowed`). A plain Convex route whose effective method and path or prefix could match a route spec's request throws `Guard.RouteShadowed` when added, and every plain Convex route answers only once the router has admitted its route spec registrations, so a router that refuses them refuses its plain routes too.
