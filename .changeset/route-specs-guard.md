A backend with route specs declares a guard: `HttpRouter.make(schema, routes, { api, guard })`. A guard is a plain Effect `HttpMiddleware` named with `Guard.make(name, middleware)`, and `Guard.none` is the explicit opt-out. Confect installs it as the router's first global middleware and runs it only for a request that dispatch would send to a route spec, OPTIONS on a route spec's path included with or without `Access-Control-Request-Method`, with `Routes.Route` and `Guard.Preflight` provided. Its inner effect never fails: a failure inside becomes Effect's response for it, and a failure whose response cannot be built becomes Effect's empty 500. A 5xx inside the guard is logged at error level with its cause, the request id and the route's function path. Inner owns the whole product lifecycle: product code runs on a fiber of its own, in a scope of its own that closes before inner answers, with a pre-response handler slot of its own, and its response's body is read there, so nothing product code holds can change what the guard settles. A handler registered by then, a finalizer's or a response conversion's included, and Effect's `HttpMiddleware.cors`, `HttpMiddleware.compression` or `HttpApiBuilder.securitySetCookie` as a product global middleware, turns the response into Effect's 500 before the guard sees it, and one registered later never runs, so after the guard only transport conversion runs. CORS on a route path is the guard's, which may itself be `HttpMiddleware.cors`; the HTTP guide shows a global CORS middleware that skips route paths. Without Effect's request state at the key Confect reads, every route request answers 500. Classification uses the router's full registration set and configuration, HEAD precedence with GET fallback, wildcard bases and the synthesized OPTIONS chain, and a global middleware that rewrites the request into another route dies before dispatch. Each `Routes.make` registration carries its own identity. `HttpRouter.make` throws `Guard.MissingGuard` when its api list reflects a route spec and no guard is given, and refuses before serving a route spec registration without a guard, one the api list does not reflect as itself (`Guard.UnreflectedRoute`), one under a product prefix, an api route spec nothing registers, and an explicit OPTIONS or any-method route that could answer a route spec's request (`Guard.RouteShadowed`). A plain Convex route whose effective method and path or prefix could match a route spec's request throws `Guard.RouteShadowed` when added, and every plain Convex route answers only once the router has admitted its route spec registrations, so a router that refuses them refuses its plain routes too.
