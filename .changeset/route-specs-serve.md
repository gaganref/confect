`Routes.make(schema, { [modulePath]: [spec, impl] })` serves each leaf's route specs over HTTP as `{ api, routes }`, one `HttpApiGroup` per leaf. Each endpoint carries the `Routes.Route` annotation, `{ functionPath, spec }`, and runs its impl through the action middleware chain with the invocation `{ name: functionPath, functionType: "action", functionVisibility: "http", args }`. Path parameters and the query (GET, OPTIONS) or JSON body (other methods) merge into the args, `returns` encodes as a JSON 200, and each declared or middleware error answers its `HttpApiSchema.status`. `Routes.make` evaluates no schema: its `api` and `routes` build on first read, and reading either throws `RouteErrorWithoutStatus` for an error without a status, so the router refuses it before serving. A failure no error schema declares, and a defect, answer 500. A route's nested `runQuery`, `runMutation` or `runAction` that Convex refuses for its arguments dies with `Routes.ArgumentValidationFailure`, which answers Effect's empty 400; `Routes.isArgumentValidationFailure(defect)` checks for it. Only that nested-call boundary reads Convex's message, so a product error never answers 400 by its message. `HttpRouter.make`'s `api` option takes one api or a list, and the action runner's invocation visibility includes `"http"`.
