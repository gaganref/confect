The internal test kernel, and `TestConfect.layer` with `target: "kernel"`, now serve HTTP routes. `fetch(path)` sends the request to the root `http` router, whose own `lookup` picks the route by pathname and method, and runs its handler as an action with the caller's identity, the request's headers and its exact body bytes. A request no route matches gets the binary's 404 `No matching routes found`, a HEAD request gets no body, and a path that does not start with `/` is refused with `InvalidFetchPath`. A route whose handler throws answers 500 with the binary's JSON error body, `{ code: "[Request ID: …] Server Error: Uncaught …", trace, data? }`, on the kernel and, on both targets, through a mounted component's bridge, where the fetch used to reject. A mounted component's HTTP module is now built only by its mount, at the mount's site URL, so a module that fails to build fails only that mount's requests. A HEAD request's 404 and 500 carry no body, a mounted component's miss answers the binary's `No matching routes found`, a GET, OPTIONS or HEAD request's body never reaches its route, and a kernel refusal inside a route rejects the fetch with that refusal instead of answering 500. A route's 500 body marks every kept secret its error carries, as a rejected call's report does, and a mounted GET or HEAD request with a body no longer throws.
