"@confect/test": minor

**Test backends now refuse a source whose push checks refuse it.** This changes the behaviour of existing test suites. A layer that built before may now die while it builds, and the test then fails before its first call.

`TestConfect.layer`, on the convex-test and kernel targets, and the `layer` of a generated `TestBackend` or component subject, now run the push checks that `PushCheck.register` registered for the app's schema and for each component a kit registers. They run once per build, before the layer serves any call. A refused source therefore never serves a call. That includes a test whose first call is an HTTP request, which runs no function's `exportArgs` and so used to reach a refused source. A generated subject runs the checks after every module loads and before any mount's `init` or `seed`. A component the test registers later with `registerComponent` runs its checks before the backend installs it, so a refused one is never callable and serves no route. Every check of the backend runs again with it. A backend with no registered check builds and serves as before.

A refusal is a defect of the backend under test, as a refused push is of a deployment. So building dies with `PushRefused`, which names the check and each refusal. It also dies with `NoPushEntry` when checks are registered for the app's schema, or a component's, but none of its functions or routers runs them, since no push would run them either. The layers' types do not change.

A mounted component's router is now built while the layer builds, and its first HTTP request reuses that router, so a router that is a component's only checked entry is checked too. It reads its mount's site URL as `CONVEX_SITE_URL` without the host's environment changing, so backends built at once each get their own. On the kernel it loads under the component's environment, the isolate's guards and the backend's seeded random stream, as the component's modules do, so its load draws the same values on every run with one seed. It used to load inside the bridge's first request, so a router that draws while it loads now draws other values than before.

The layer finds a component's checks from its own module loads: a schema a module registers checks for while the component's load evaluates it, or a module it imports first, belongs to that component, and stays with the loaded module once it is cached, so a later backend that loads the same module names it again. A registration counts only for the target whose load it ran in, never for one that merely reaches the module through imports, and a schema whose checks another target's entries run is that target's. This only detects a misconfigured kit: a component with registered checks but no guarded entry. It is not the guard. This detector does not see a registration made by a module that is evaluated outside any build's load scope: one the test imported first, one code outside any load evaluated, or one an earlier load by another target evaluated and that this target reaches only through its own modules' imports. Nor does it see one made by a module several components share, after the first of them loads it. For those kits, pass `databaseSchema` to get `NoPushEntry`. Their guarded entries are still checked at build and at push. A registration made while one target's load runs inside another's refuses the build with `PushCheckUnattributed`, which says to pass `databaseSchema`, unless a target names that schema as `databaseSchema` or its entries run its checks, which settles it for that build and for any build whose load encloses it, never for an unrelated one. No generated file changes. A suite that replaces `process.env`, or puts back one it saved, keeps every mount's site URL; a mounted backend refuses with `SiteUrlOverrideUnsupported` when an older loaded copy of `@confect/test` installed the proxy.

A test that builds a refused source on purpose, such as one that asserts a call's own refusal, passes `pushChecks: "skip"` to the layer:

```ts
TestConfect.layer(schema, convexSchema, modules, { pushChecks: "skip" });
```

These runs are apart from the memo Convex's analysis uses, so a test that builds several backends over one module graph runs the checks once for each build. To find the checks, a build evaluates the backend's modules before the first call rather than at it. The kernel loads them under its own rules, and its open reuses that load. The convex-test target imports each module a deployment would register as a function. A module or mounted router that fails to load, whether its loader rejects or throws, still fails only the call that loads it, as before. The checks it registered before it failed count for its target and run with the rest, so a load that registers a refusing check and then fails refuses the build, or the registration. Later registrations run one at a time, each verifying every component installed before it, and a call made while one is pending waits for it to settle. A later registration whose verification does not pass, refused or failed, refuses the whole session: every later call, HTTP request and scheduled run dies with that refusal or failure until a later registration's verification of every installed component passes. `Preflight.run` is now only for a backend built another way, such as `convexTest` directly.

`PushCheck.register` in `@confect/server` now also tells the observers in the set under `Symbol.for("@confect/server/PushCheck/observers/v1")` of each schema it registers a check for, which is how `@confect/test` traces a component's checks.
