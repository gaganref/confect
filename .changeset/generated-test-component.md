When a component can import `@confect/test`, codegen writes a `TestBackend` export built by the new `TestComponent.make`: its public functions, callback slots, its own `init` from its descriptor, laws, ports, mounts and settings, and `export`, `laws` and `callback` obligations, with no groups and no access or realm proof. A handle whose contract `confect/callbacks.ts` does not export stops codegen with `UndeclaredCallbackSlotError`. Its layer opens on the kernel as an app's does, after running the component's own `init` with typed `install` args. It gives a runtime without `withIdentity`, and holds each call to a slot's handle, scheduled ones included, as a pending command the test answers with a drawn return or a declared error. `TestComponent.exports` and `TestComponent.callbacks` take cases total over functions, slots and outcomes, and `TestBackend`'s app subject now carries `kind: "app"`. `MountSteps.run` takes an optional root step, a mounted backend's own `init` and whether its steps follow, run by the same per-step code as each mount. Codegen resolves a component's descriptor from the component's own root, through its package's `./client` export as Node resolves it or `client.ts`, and refuses one that is declared but does not resolve or is no descriptor. A slot call whose arguments break its contract is refused before it is held, as the binary refuses it. A slot's answer is checked against the slot's declared return, and refused as the binary refuses a handle's return. Both checks port the binary's own, field order, literal messages and value printing included, and read an id by its table number in the subject's root namespace, as the binary reads it in the host's.
