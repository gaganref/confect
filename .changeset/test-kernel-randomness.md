The test kernel's random sources draw from a supplied stream in every kernel function and module load: Confect and plain Convex functions, component functions and lazily imported modules alike. A function draws from its bound invocation's stream, or else from the backend's own world, so unbound `TestConfect.layer` calls on the kernel target now draw from the stream the layer's `seed` starts and replay, where they drew the host's. With neither, a draw refuses with `FunctionRandomUnavailable`. `crypto.getRandomValues` answers as the Convex binary's does: a fill past 65,536 bytes throws `TypeError`, a non-integer array throws the binary's `TypeMismatchError`, and a detached call draws. `crypto.randomUUID` draws from the stream too. A module that draws while it loads draws from the stream of the backend's world, and with no world the open refuses with `LoadRandomUnavailable`. `crypto.subtle` operations that draw cryptographic randomness reject with the binary's error in a query, a mutation and a module load, and with `RequiresBinary` in an action. A bound handler on the convex-test target, which `TestConfect.layer` pins through the invocation bridge, refuses the same `subtle` operations by function type.
