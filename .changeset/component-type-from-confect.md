Breaking change. Every `confect/_generated/components.ts`, the host's and that of any Confect component that mounts components, types each mount of an in-repo Confect component from the component's `confect/_generated/component.ts`, which now exports `ComponentApi` beside the contract. A mounted definition directory is an in-repo Confect component when the `confect/_generated/id.ts` beside it records that directory in its `IdScope.component(...)` line, which only component codegen for that directory writes. Codegen parses the line, so formatting and line endings do not matter, and the directory can have any name. Before, the registry imported the component's `convex/_generated/component.js`, which only Convex writes. Projects committed a hand-written stub there, and Convex overwrote it on every push. A component mounted by package name and an in-repo plain Convex component keep reading `<definition>/_generated/component.js`. `confect codegen --component-dir` now creates the definition directory when it is missing, and stops before writing anything when the component's `id.ts` records a different directory. It also writes `<dir>/.gitignore`, which ignores the `_generated/` folder Convex writes beside it and nothing else. That file is codegen output: codegen replaces any other content in it and restores it when it is deleted. Codegen writes it for a Confect component only, never for an app or a plain Convex component.

Who is affected: a host, or a Confect component, that mounts an in-repo Confect component. Its registry names a new module, so the mounted component's contract must be regenerated before the host type-checks. Host codegen run first gives the mount Convex's `<definition>/_generated/component.js`, which a fresh clone reports as `TS2307`. Rerun host codegen after component codegen.

To migrate:

1. Rerun `confect codegen --component-dir <component>/convex` for each Confect component, then `confect codegen` for the host.
2. Delete any hand-written `<component>/convex/_generated/component.ts` stub and commit the `<component>/convex/.gitignore` that component codegen writes. Convex writes `<component>/convex/_generated/` on each push, overwrites `component.ts` with its own, and deletes any other file it did not write. Move any rule of your own out of `<component>/convex/.gitignore`, because codegen replaces that file. A hand-written ignore rule for the component's `convex/_generated/` elsewhere is now redundant.
3. Import `ComponentApi` from `<component>/confect/_generated/component` where code imported it from `<component>/convex/_generated/component`.
4. If plain Convex host code calls an in-repo Confect component through `convex/_generated/api`, ignore the host's `convex/_generated/` too, or import `components` from `confect/_generated/components`. A tracked `api.d.ts` that imports an ignored component folder leaves those calls untyped without an error.
5. A test that globs a Confect component's `convex/**` into convex-test adds a stand-in `_generated` key, or registers the component through Confect's generated `confect/_generated/testing.ts`.
6. A package that ships a Confect component maps its `./_generated/component.js` export to `confect/_generated/component`, or to a file outside any `_generated/` folder that re-exports it.
7. A workspace-linked package that ships a TypeScript `convex.config.ts` gets `api.ts`, `component.ts`, `dataModel.ts` and `server.ts` written into the `_generated/` beside it on each push. A Confect component's own codegen ignores that folder. For a plain Convex component, git-ignore it by the package's path.
8. A package that ships a Confect component stops packing `convex/_generated/`. `npm pack` and `pnpm pack` read the component's `convex/.gitignore` under a `files` allowlist, leave out that folder and the `.gitignore` itself, and pack every other file as before. A `.npmignore` in the component's `convex/` replaces that rule for packing.
