Deployment credentials come from a run-time `DeploymentAccess` service, and the deploy path keeps none in Alchemy state under any access kind. `Confect.Backend`, `Convex.Code`, `Convex.EnvironmentVariables` and `Convex.LogStream` no longer take `deployKey`, and `EnvironmentVariablesAttributes` no longer holds one. Choose the access with `Convex.providers({ access })`. `Convex.DeploymentAccess.grant`, the default, needs a project-scoped management login. One `GET /token_details` per run, before the first request the access serves to a deployment, refuses a team-scoped login with `DeploymentGrantRefused`; management resources such as `Convex.Project` and `Convex.Deployment` are outside that check. Keys whose names match what the grant check generates are refused with `DeploymentGrantRefused` before a key is created. The returned key is used unless the deployment then lists a key under the attempt's name. If the returned key is not the management login, the run fails with `DeploymentGrantUnproven` reason `Minted`; deleting that key is attempted, `deleted` says whether it succeeded, and `keyName` records the name to remove by hand if not. If the returned key is the login, that listed key may be the grant itself, so nothing is deleted and the run fails with reason `LoginKeyListed`. `Convex.DeploymentAccess.deployKey(keys)` takes one key or several, each serving the deployment its prefix names. Local providers read the local backend's admin key at run time. Server and CLI text in errors, spans and diagnostics, a failed function's path included, is redacted against every credential the run handled, including the token after each `|`.

Migration: delete each `deployKey` prop. A stack that read `CONVEX_DEPLOY_KEY` passes `access: Convex.DeploymentAccess.deployKey(Config.Redacted("CONVEX_DEPLOY_KEY"))` to `Convex.providers`, and a stack with a key for each of several deployments passes them all as an array. A stack that passed `key.deployKey` from `Convex.DeployKey` drops the prop, and under an OAuth grant drops the `DeployKey` too. A team access token is refused under `grant` with `DeploymentGrantRefused`; supply a deploy key instead. Under `alchemy dev`, remove `Convex.DeployKey`, which now fails with `DeployKeyUnavailableLocally`.

`Convex.DeployKey` remains an explicit opt-in for minting a named key, and a stack that declares it stores that key in state. It deletes by the key name Convex lists, never by its secret, and fails with `DeployKeyNotMinted` when Convex lists no new key after a create. `ConvexClient.deleteDeployKey` takes a key name, `ConvexClient.getTokenDetails` reads the login's scope, and `ConvexClient.createDeployKey` returns `reusesLogin`. Under `grant`, `DeploymentAccess.api` can fail with `DeploymentGrantRefused` or a `ConvexClientError` from the scope check. Deployment calls on `ConvexClient` accept an absent key, meaning the management login. `DeploymentAccess` and the `EnvironmentVariables` and `LogStream` providers and layers are marked unstable.
