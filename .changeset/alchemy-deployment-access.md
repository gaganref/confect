Deployment credentials come from a run-time `DeploymentAccess` service, and the deploy path keeps none in Alchemy state under any access kind. `Confect.Backend`, `Convex.Code`, `Convex.EnvironmentVariables` and `Convex.LogStream` no longer take `deployKey`, and `EnvironmentVariablesAttributes` no longer holds one. Choose the access with `Convex.providers({ access })`. `Convex.DeploymentAccess.grant`, the default, needs a project-scoped management login: it refuses a login `GET /token_details` calls team scoped, and keys an earlier grant check left, with `DeploymentGrantRefused` before any write, then uses the key Convex returns when the create lists no new key. A login that mints a key fails with `DeploymentGrantUnproven`, after its attempt's own key is deleted. `Convex.DeploymentAccess.deployKey(keys)` takes one key or several, each serving the deployment its prefix names. Local providers read the local backend's admin key at run time. Errors, spans and diagnostics are redacted against every credential the run handled, including the token after each `|`.

Migration: delete each `deployKey` prop. A stack that read `CONVEX_DEPLOY_KEY` passes `access: Convex.DeploymentAccess.deployKey(Config.Redacted("CONVEX_DEPLOY_KEY"))` to `Convex.providers`, and a stack with a key for each of several deployments passes them all as an array. A stack that passed `key.deployKey` from `Convex.DeployKey` drops the prop, and under an OAuth grant drops the `DeployKey` too. A team access token is refused under `grant` with `DeploymentGrantRefused`; supply a deploy key instead. Under `alchemy dev`, remove `Convex.DeployKey`, which now fails with `DeployKeyUnavailableLocally`.

`Convex.DeployKey` remains an explicit opt-in for minting a named key, and a stack that declares it stores that key in state. It deletes by the key name Convex lists, never by its secret, and fails with `DeployKeyNotMinted` when Convex lists no new key after a create. `ConvexClient.deleteDeployKey` takes a key name, and `ConvexClient.getTokenDetails` reads the login's scope. Deployment calls on `ConvexClient` accept an absent key, meaning the management login. `DeploymentAccess` and the `EnvironmentVariables` and `LogStream` providers and layers are marked unstable.
