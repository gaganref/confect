# Fork changes

This hand-maintained record was rebuilt when the fork moved to this repository.
It records the changes carried beyond the upstream release base and complements
package changelogs. It is not generated by Changesets. Update it in each fork PR
with what changed, why, changeset coverage, and upstream intent or proposal.

Upstream status was checked on 2026-10-16. **Planned** marks a patch intended for
an upstream proposal. It does not imply that a proposal has been submitted or
accepted. **Unrecorded** means the reviewed change and changeset do not establish
submission intent. Fork-specific publishing and branch automation stay **fork
only**. Upstream submissions go through the maintainer. A backport remains listed
until the fork adopts a release containing it.

## Counted HTTP bodies

Add `HttpRouter.withBodyLimit` for endpoint middleware. Count bytes while reading,
return 413 at the cap and 415 for non-identity content encoding. Verification and
payload decoding share one buffer. Effect 4.0.4's Web readers do not provide these
guarantees. Changeset: `counted-http-body.md`. Upstream: planned; no proposal submitted.

## OPTIONS middleware dispatch

Route OPTIONS requests through the declared path's middleware, never its handler.
Preserve explicit OPTIONS handlers, component prefixes and route middleware.
Changeset: `route-options-middleware.md`. Upstream: planned; no proposal submitted.

## HTTP identity states

The module-level `Auth.getUserIdentity` effect returns `Absent`, `Valid` with
Convex's verified identity, or `Invalid` when Convex rejects the identity read.
HTTP handlers and middleware can handle missing and invalid credentials without
catching defects. The existing service member keeps its identity-or-error
contract. Interruption remains interruption, and each execution reads identity
again. No raw token parsing or timing claims are added. Changeset:
`http-identity-states.md`. The local-backend suite covers absent, accepted,
bad-signature and foreign-issuer requests with self-minted RS256 test keys.
Upstream: planned; no proposal submitted.

## Native function reference conversion

Move `Ref.getFunctionReference` to `@confect/core/RefInternal`. The `Ref` module
and the package barrel no longer export the converter. Import it directly:

```ts
import { getFunctionReference } from "@confect/core/RefInternal";
```

The converter keeps the same types, supplied native references, and cache by
function name. Core, JavaScript, React, and server callers use the new subpath.
Generated refs still use `Refs.make(spec)`. A separate import lets component
projects ban native reference conversion without banning `Ref` types and codecs.
Frame's official wrappers must update their imports when they take this build.
Changeset: `ref-internal-subpath.md` marks this as breaking. Upstream: planned;
no proposal submitted.

## Schema bundle imports

Serve Scalar CDN docs without importing Effect's inline Scalar module. Effect
4.0.6 introduces a dynamic import there, and Convex's name-preserving schema
bundler emits a shared chunk even when the inline renderer is unused. Both
barrel and subpath table imports remain supported. The packed consumer now has
a table, uses Effect 4.0.6, and bundles its generated schema with Convex's options
before checking the exported table. The local-backend consumer shares that table
fixture. Changeset: `schema-bundle-imports.md`. Upstream: planned; no proposal
submitted.

## Profile manifest sections

Profiles describe app functions in import-free manifest sections, including their middleware. Codegen identifies definitions by key, owner and format, rejects reserved keys and conflicts, and includes sections in the digest. Incremental spec edits update and remove sections without a full rebuild. Changeset: `profile-manifest-sections.md`. Upstream: planned; no proposal submitted.

### Validate sections against previous output

Codegen checks previous section data, prints notes and removes the manifest only when the section step fails. Unreadable, empty, missing-default and null previous manifests act as empty history. The early declaration write preserves previous sections, so unrelated failures retain history. Unchanged runs write nothing; a spec-only section edit writes the manifest once. A section that loses its last participant gets one generic note naming its former functions, without running a callback. Full and incremental generation share this behavior. Declaration edits replace reserved fields rather than restoring them from history. Thrown checks become typed diagnostics and every failing section is reported. Changeset: `profile-manifest-checks.md`. Upstream: planned; no proposal submitted.

### Require JSON description values

Descriptions must be JSON data. Non-JSON values, including `Date`, `Map`, `Set` and class instances even with a `toJSON` method, getters, non-enumerable properties, arrays with properties besides their elements, symbol keys, and own `__proto__` properties fail with a typed diagnostic naming the section, function, declaring spec and exact JSON path. Empty property names retain `[""]` in the path and cycle refusals identify the cyclic reference. Refusing `__proto__` prevents object-literal prototype semantics from changing the manifest on readback and making unchanged runs write repeatedly. Section failure cleanup removes the manifest. Changesets: `profile-manifest-json.md`, `manifest-json-tojson.md`. Upstream: planned; no proposal submitted.

### Report description refusals accurately

A manifest section's deliberate description refusal names the section and
function without claiming its value was not JSON. Non-JSON values still name
their exact JSON path. Changeset: `manifest-description-errors.md`. Upstream:
planned; no proposal submitted.

### Attribute section checks to the section

A failed manifest section check names the section key instead of the first
participating declaration. Its conflict detail keeps both function paths.
Thrown checks use the same section attribution. Changeset:
`manifest-section-check-errors.md`. Upstream: planned; no proposal submitted.

### Generate files from sections

A section's optional `generate` writes one file into `confect/_generated`. Codegen bundles each `confect/` module the section matches and passes `render` their exports, every registered function with its spec file, and each mount with its definition specifier. Each returned error string is a typed error under the section key. Codegen refuses a built-in name, a name outside `_generated` and a name two keys claim, and removes a section file once no section claims it. Every registration file and the declared HTTP router import each section file first, and incremental spec edits render it again. `confect dev` regenerates when a file the section accepted, or a `confect/` file it imports, changes or is removed, including after a refusal or a load failure. Codegen checks the router's imports after it writes the run's section files, so a regeneration from an empty `_generated` accepts them. Frame's observe door needs this to load module declarations before any handler runs. Changesets: `manifest-section-generate.md`, `manifest-section-clean-regenerate.md`. Upstream: planned; no proposal submitted.

### Show render every offered file

A generating section's `render` also receives `files`, every `.ts` file under `confect/` outside `_generated` that `match` was offered, so a section can see a folder whose files it does not load. `confect dev` now regenerates when any such file is removed, as it already did when one is added. Frame's authz section needs this to list every module folder. Changeset: `manifest-section-render-files.md`. Upstream: planned; no proposal submitted.

### Summarize a section's data

A section's optional `summarize` returns its whole manifest data from the modules its `generate` matched and its functions' descriptions, in place of `{ format, functions }`. Codegen runs it after `describe` and before `check` and the digest, and refuses a result that is not JSON data or does not carry the section's format. Section files now render before the manifest step so their modules load once. Frame's observe catalogue needs this for `observe: { format: 2, fields, functions }`, with each function's module and arguments. Changeset: `manifest-section-summarize.md`. Upstream: planned; no proposal submitted.

### Show summarize each function's spec file

A section's `summarize` also receives `sources`, the spec file under `confect/` that declares each of its functions, keyed by function path. Frame's observe catalogue reads a function's module from its folder, and matching every spec per section cost about 0.4 s per section on Docket. Changeset: `manifest-section-summarize-sources.md`. Upstream: planned; no proposal submitted.

## Reserved arguments

Profiles and internal mutation, action and Node action constructors can reserve one argument without changing domain schemas or visibility. Refs, including component refs, retain the name. Registration accepts any optional value, strips it before decoding and refuses domain collisions. Queries ignore the option to preserve cache keys. Changeset: `reserved-argument.md`. Upstream: planned; no proposal submitted.

Reserving invocations expose `{ value, requestId, deployment }` through `RegisteredFunction.Received` at root creation. The runner reads the cloud URL and passes only the request ID from private request metadata. Queries and unreserved functions have no received value; calls without a runtime layer add no metadata reads. Changeset: `received-argument.md`. Upstream: planned; no proposal submitted.

`RegisteredFunction.Forward` supplies context from the active call boundary for reserving refs. Mutation/action runners, action-call profiles, mutation transaction calls and scheduling add it after encoding. An absent, undefined, throwing or unserialisable provider leaves the call unchanged. Queries and non-reserving component calls receive nothing. Each action-call profile call opens an `ActionCall.call` span. Scheduling opens named spans whose successful exit is the job ID; argument encoding now runs when the scheduling effect executes. Changeset: `forward-argument.md`. Upstream: planned; no proposal submitted.

`OfficialComponent.encodeCall` requires `{ carrier: "forward" | "none" }` as its
third argument. `forward` uses the existing reserved-argument encoder to include
the caller's carrier for reserving mutations and actions. Queries and
non-reserving targets receive no carrier. `none` preserves the previous wire
arguments for components that replay or compare stored arguments. Changeset:
`official-component-carrier.md` (required call-site migration).
Upstream: planned; no proposal submitted.

The existing local-backend CI job exercises generated registrations with arbitrary incoming context, runner hops, an inline owned counter component, an ordinary strict component call and persisted scheduled context. The local-backend fixture app always runs with a runtime layer; unit and mock-backend suites cover the no-layer path. Scheduled polling uses live time. Native API additions come from the registered validators without starting a backend. Changeset: `reserved-argument-backend.md`. Upstream: planned; no proposal submitted.

The local-backend reserved-argument test gives each scheduled chain a random
`run` value. The scheduled read selects the current run's record even when the
backend preserves earlier results. The test keeps every transport assertion.

Changeset: none; test isolation only.
Upstream: unrecorded; submission goes through the maintainer.

### Refuse domain collisions in codegen

Full and incremental codegen reject a domain argument reserved by its profile before loading its implementation. The diagnostic names the spec file, function and argument. Registration retains its load-time backstop. Changeset: `reserved-argument-fence.md`. Upstream: planned; no proposal submitted.

### Forward context through callback handles

`Callback.handle(contract, { reservedArgument })` retains the reservation on
decoded mutation and action handles. The existing runners and scheduler then
forward context, including a run id, to a host target that reserves the same
name. Query handles and handles without the option keep their previous
behavior. This carries values without adding a trust policy. Changeset:
`callback-reserved-argument.md`. Upstream: planned; no proposal submitted.

## Invocation instrumentation

Add invocation root spans and an optional `confect/runtime.ts` layer so applications can install Effect tracers and loggers without duplicate console logging. Preserve original declared failures for tracers, encoded client errors and query caching. Cache each layer context once per isolate so permanent scope ownership stays bounded. Changeset: `invocation-observability.md`. The root span ends with the outcome the client gets: a failure in a function with no error schema, other than a raw `ConvexError`, ends it as a defect, and so does an error encoding that dies with a `ConvexError`. Changeset: `undeclared-failure-span-defect.md`. Upstream: planned; no proposal submitted.

HTTP accepts the same layer explicitly on hand-built routers and receives `runtime.ts` through generated declared entries. Reuse Effect's request span, continue remote traces, and expose original endpoint failures through Effect 4.0.4's `ErrorReporter` before response conversion. Function and HTTP invocations share one layer build per isolate. Changeset: `http-invocation-observability.md`. Upstream: planned; no proposal submitted. Omit request middleware without a runtime layer. Owners needing ignored HTTP failures implement the raw ErrorReporter interface, with per-span deduplication.

## Database writes

### Observe writes in their transaction

`DatabaseWriter.make` and `layer` accept an optional hook with table-discriminated,
decoded before/after documents. Mutation middleware can install it on internal
functions to maintain aggregates, schedule work and record writes. A hook defect
rolls back the mutation. Writers without a hook retain their existing read cost.

The mock-backend fixture installs the hook through profile middleware and an
explicit internal-mutation attachment. Missing-document patches retain their
typed failure. Raw and separately installed writers bypass the hook; concurrent
same-document writes require sequential awaits for exact snapshots.

Changeset: `database-write-hook.md` (minor).
Upstream: planned; no proposal submitted.

### Patch writes an encoded delta

Encode only the patched fields, each through its own codec, and call native
`patch`, so a patch leaves the rest of the stored document unchanged. An omitted
field's codec never runs. Other failures keep their error classes.

What changes for a consumer:

- Untouched fields are no longer re-normalised by their encoders. An untouched
  `"001.00"` under `FiniteFromString` is no longer stored again as `"1"`.
- Fields outside the schema are no longer removed by a patch.
- A patch can repair a stored field that no longer decodes, because the complete
  result must decode before the write.

A union, a transformation over the whole struct, a check on the struct itself or
an index signature keeps the full replace. The first two can make one field's
encoding depend on another, a struct-level check must see the decoded values
before encoding, and a key under an index signature has no field codec.

Changeset: `patch-encoded-delta.md`.
Upstream: planned; no proposal submitted.

## React pagination

### Keep a page while its replacement fails

`StreamPagination.interpret` treated a failed replacement as a result. A failed
pin then swapped the loaded page out for the failure. A failed split replacement
stayed hidden while its sibling was still loading. Now a failed replacement fails
the interpretation at once, the replaced page and every page after it stay in
`Failed.items`, and the page and its replacements stay subscribed for a retry.
A page whose own result fails still ends the items, since its range is unknown.
`Failed` also carries the transitions the pass found, and the hook applies them,
so the other pages keep splitting and swapping while the failure shows.

`interpret` also reports `firstPageLoaded`, which holds once the head page has
its full result. The hook used one page as the sign of a loading first page, so
recursive splits of the first page reported `LoadingMore` with no items.

Changeset: `stream-pagination-page-swaps.md`.
Upstream: deferred; no proposal for now. The maintainer decides when to send one.

## Component authoring and contracts

### Describe public functions

The five public function builders accept an optional `description` and keep it
on the spec through middleware, so contract tools can read it. A call without a
description keeps its inferred type. Internal builders take none.

Changeset: `function-description.md`.
Upstream: planned; no proposal submitted.

### Extend the public builders

`FunctionSpec.extend<Fields>()({ middleware })` returns the five public
builders with extra required fields typed from each function's args and the
middleware on every spec. Specs keep the fields; plain builders are unchanged.
`extend` refuses fields named after builder options and middleware an earlier
layer attached, checking every middleware an array's element type allows. A
builder refuses a field named after an option that the fields add only for its
function's name.

Changeset: `function-extend.md`.
Upstream: planned; no proposal submitted.

### Attach middleware through a profile

`Profile.attach(spec, info => options)` puts a middleware with options in a
profile's list, its options computed from each function's name, fields and args
thunk, so codegen's registration runs it on every function the profile builds.
An extension may attach it again, as a middleware with options may repeat.
`attach` refuses a middleware without options, which joins the list directly
and at most once.

Changeset: `profile-attach.md`.
Upstream: planned; no proposal submitted.

### Wrap a profile's schema thunks

Add `schemas` beside a function profile's middleware, with typed wrappers for
args fields, returns, items and error unions. Wrappers run at first force and
compose outside earlier layers. Absent args, returns and item thunks stay absent.
Profiles can check or transform declared schemas without a facade. Core adds no
contract or authorization policy.

Changeset: `profile-schema-wrappers.md`.
Upstream: planned; no proposal submitted.

### Supply a profile error default

An error wrapper opts into `Schema.Never` when a function declares no error.
A profile can add its own error to every union, including the empty one.
Refuse a wrapper whose output for the empty union still has type `never`, so
client return types agree with the presence of an error schema.
Preserve lazy construction, middleware types and the pagination guard across
all ten public builder forms, including tagged-error subclasses and extensions.

Changeset: `profile-error-default.md`.
Upstream: planned; no proposal submitted.

### Read descriptions in profile callbacks

Expose the optional function description in `Profile.Info` to both middleware
attachment factories and lazy schema wrappers. A callback can check a declared
description without forcing a schema; an omitted description stays absent.

Changeset: `profile-info-description.md`.
Upstream: planned; no proposal submitted.

### Require descriptions through a profile

A profile may declare `description: string` to require that builder option on
all five public builders. The description stays on the spec and in callback
info, outside custom fields. Other description types and all other builder
option names remain refused at `extend` or the name-specific builder call.

Changeset: `profile-requires-description.md`.
Upstream: planned; no proposal submitted.

### Check component declarations

Carry a literal app or component kind in backend declarations. Default to app,
require `kind: "component"` for components, and reject component declarations in
`Auth.make`. Reject codegen targets whose kind differs from the declaration and
callback contracts exported from `confect/callbacks.ts` whose IDs do not start
with the component's `defineComponent` name followed by `/`.

Changeset: `check-component-declarations.md`.
Upstream: planned; no linked proposal verified.

### Author Convex components

Add component codegen and dev modes, published contracts, `Component.bind`,
scoped services, schemas and IDs, HTTP routes, and test registration. Components
can expose decoded arguments, results, and declared errors across installation
boundaries while retaining a vanilla Convex wire API. Port upstream's component
work to stable Effect and prove nested isolation, errors, pagination, env, crons,
and storage on the supported backends.

A component's generated services omit the raw `MutationCtx`, `QueryCtx` and
`ActionCtx` imports and value/type exports. Use the typed database, runner,
storage and scheduler services in component handlers. Host generation is
unchanged. The server package still exports the raw tags for middleware;
removing them from a downstream runtime context belongs to that middleware.

A component's generated `_generated/component.ts` builds its contract with
`Component.contract(spec, scope, tables)`, the name `Component.make` had. The
rename frees `Component.make` for the component descriptor. Breaking change:
replace `Component.make(spec, scope, tables)` with
`Component.contract(spec, scope, tables)`. Rerun `confect codegen` for
generated callers.

A component package describes itself with `Component.make(name, { env, client })`,
and a host declares each mount's client with `Mount.make(component, { name,
httpPrefix, env, options })` in `confect/<mount>.ts`, mirroring Convex's
`defineComponent` and `app.use`. A mount is a `Context.Reference` whose default
is the component's client over that installation, so a handler yields it with no
Layer and a test replaces it with `Effect.provideService`. `env` is typed from the
descriptor and `options` from its client constructor. A descriptor may name its
`init`, an internal mutation, and each mount then passes install `args` typed
from it; a callback slot takes only an internal host ref matching its contract.
The mount records `args`; nothing runs `init` on a push yet. A host lists its
mounts in `App.make({ components, mounts })`, and codegen writes each one's
`app.use`. `Auth.siteUrl` takes a mount with an `httpPrefix`. A descriptor
that passes its `contract` gives each mount `callbackArgs(slot)`, a callback
contract's args with component ids typed for that mount.

Changesets: `add-confect-components.md`, `component-no-raw-ctx.md`,
`component-contract-rename.md`, `component-descriptor-mount.md`,
`mount-install-args.md`, `mount-site-url.md`, `app-mounts-list.md`,
`mount-callback-args.md`.
Upstream: port of [upstream #646](https://github.com/rjdellecese/confect/pull/646),
which remains open; fork-specific follow-up submission is unrecorded.

### Name the field that groups a component table's rows

`Table.make(...).group("batchId")` names the required id field that groups a
table's rows and refuses any other field. `Component.contract(spec, scope,
tables)` takes tables beside system table names and refuses a grouped table whose
id is not one of them, in the component's scope, and a table entry that may be
absent, such as any union in the tables. `Component.groups(contract)`
returns each grouped table's `{ key, table }`, typed with the literal key and
table. Table names alone, even as an explicit type argument, carry no groups.
Codegen passes each table to the contract, so a generated contract lists its
groups and its declared type keeps them. The generated
`_generated/component.ts` binds its own imports with a leading `$`, as
`convexSchema.ts` does, so a table named `spec`, `scope` or `component` cannot
collide with them. Rerun `confect codegen` to publish groups.

Changesets: `table-group.md`, `codegen-table-groups.md`.
Upstream: planned; no proposal submitted.

## Backend declarations and HTTP routing

### Require middleware on every registered function

Add `App.make({ requiresMiddleware })` and emit the requirement in each group's
registration. Codegen fails once with every uncovered function's group path and
name, including internal and raw Convex functions.
`GroupImpl.finalize({ required, groupPath })` also rejects uncovered functions
when registration layers build. Requirements are matched by middleware key
against actual registry attachments so function and group middleware both count
without loading component definitions into function bundles. Preserve the
requirements when dev regenerates registration after a spec edit.

Changeset: `require-function-middleware.md`.
Upstream: planned; no linked proposal verified.

### Declare a backend in `confect/`

Add `Env`, `App`, `Auth`, `Http`, and `Manifest`. Generate Convex configuration,
auth, HTTP entry points, and an import-free deployment manifest from the backend's
declaration so handlers, component mounts, and infrastructure share one contract.
Watch declarations in dev mode and reject conflicting routes and hand-written
owned outputs. Components can declare their env and mounts the same way.
Raise core's Convex peer floor to 1.39.0 for component env declarations.

`App.make({ env, components, mounts })` takes the `convex.config` definitions of
the components a backend mounts and its `Mount.make` mounts as lists, so each
mount's name is written once. Codegen writes one `app.use` per mount, in list
order, with the definition whose `defineComponent` name is the mount's component
name. It fails when a mount has no listed definition, when a listed definition
has no mount, when two mounts share a name, and when two listed definitions

## Query streams

### Defer stream checks until consumption

Add `QueryStream.defer` with a known layout and direction. An effectful check
runs when the source is pulled, including inside `flatMap`, and stays lazy

Changeset: `deferred-query-stream.md`.

### Collect a whole stream or fail

Add `QueryStream.collect` with row and byte budgets. It returns an array only
after the source completes; a budget stop fails with `ReadBudgetExceededError`.
An exact row or byte limit succeeds on completion, including zero for an empty
stream. At either limit, collection and pagination may read one counted,
unreturned lookahead row to detect an overrun.

Changeset: `collect-query-stream.md`.
Upstream: planned; no proposal submitted.

### Default stream sinks to 2,000 row reads

`paginate` and `collect` use a 2,000-row budget unless the caller supplies a
limit. Pagination can return `SplitRequired`; collection fails rather than
returning partial data. Plain Effect Stream consumption keeps its enclosing
budget, or remains unlimited when none is supplied.

Changeset: `default-query-stream-budget.md`.
Upstream: planned; no proposal submitted.

### Bind and seal pagination cursors

`paginate` accepts an effectful `cursorEnvelope`. It opens both input cursors
before decoding or reading and seals every outgoing continuation and split,
including unchanged cursors and end sentinels. A refused envelope produces
`InvalidCursor`. The caller owns the envelope's policy and cryptography, and
sealing equal inputs must produce the same string for stable cursor equality.

Changeset: `query-stream-cursor-envelope.md`.
Upstream: planned; no proposal submitted.

### Deduplicate overlapping stream ranges

`QueryStream.merge(streams, { dedupe: true })` emits equal complete keys once,
including their ID tiebreakers. It retains the first visible copy in source
order, resolves a whole key group before publishing its cursor boundary, and
preserves the option through narrowing and reversal. Ordinary merge is unchanged.

Changeset: `merge-query-stream-dedupe.md`.
Upstream: planned; no proposal submitted.
